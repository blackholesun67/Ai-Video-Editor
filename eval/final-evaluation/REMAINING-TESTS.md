## Objective 3 — คำบรรยาย (Subtitle)

| หัวข้อ | รายละเอียด |
|---|---|
| **ต้องทดสอบอะไร** | (1) ความแม่นยำของข้อความซับเทียบเสียงจริง (2) ความแม่นยำของจังหวะเวลาขึ้น/ลงซับ (3) ใช้งาน editable-subtitle (แก้ซับในหน้าเว็บ) ได้จริงไหม |
| **คนถอดเสียงอ้างอิง** | ขั้นต่ำ **1 คน** ถอดทุกคลิปที่เลือก (Must do) — แนะนำ **2 คน** ถอดอิสระจากกันอย่างน้อย 1 คลิป เพื่อเช็ค inter-transcriber agreement (Should do) |
| **จำนวนคลิป** | ขั้นต่ำ **2 คลิป** (Must do) แนะนำ **3 คลิป** (Should do) |
| **วิธีเลือกคลิปไม่ให้ bias** | เลือกจากชุด V02–V07 ตามเกณฑ์ตายตัวที่กำหนดไว้ล่วงหน้า **ก่อน**เห็นผลของระบบ: (1) เลือก 1 คลิปที่มีคำเฉพาะทาง/ชื่อเฉพาะเยอะ (เช่น V04) (2) เลือก 1 คลิปคำพูดทั่วไป (เช่น V02) (3) ถ้าเลือกคลิปที่ 3 ให้เลือกคลิปที่มีอักษรละตินปน (ผ่าน AI-Correction จริง — เช็คจาก log `[AI-Correct]` ของ Objective 1) เพื่อวัด corrected-text ด้วย — **ห้ามเลือกหลังเห็นผลว่าคลิปไหนซับออกมาสวย** |
| **การถอดต้องเป็น blind** | คนถอดฟังจากไฟล์เสียงดิบ (`full_audio.wav`) เท่านั้น **ห้ามดูผลลัพธ์ของระบบหรือ `ground_truth.txt` เดิมระหว่างถอด** กันไม่ให้ถอดเอนไปทางที่รู้อยู่แล้วว่าระบบจะทำอะไร |
| **Metric ที่ใช้วัด** | **ยังไม่ยืนยันจาก Test Plan ฉบับจริง** (ไม่พบในโค้ด repo) ข้อเสนอเบื้องต้นถ้าไม่มีการกำหนดไว้: **WER (Word Error Rate)** หรือ **CER (Character Error Rate)** สำหรับความแม่นยำข้อความ (ภาษาไทยไม่มีช่องว่างระหว่างคำชัดเจน จึง CER อาจเหมาะกว่า WER — ต้องพิจารณาตอนใช้จริง) + **timing offset** เฉลี่ย/สูงสุด (วินาที) ระหว่างขอบเวลาซับกับขอบเวลาเสียงจริงอ้างอิง ต่อบรรทัด |
| **Editable subtitle test** | คนทดสอบจริง 1 คนขึ้นไป แก้ข้อความ+เวลาอย่างน้อย 1 บรรทัดต่อคลิป ผ่านหน้า `SubtitleEditScreen.jsx` → render → ตรวจว่าไฟล์ output ตรงตามที่แก้ (pass/fail) |
| **Evidence ที่ต้องเก็บ** | `reference/<case>/transcript.txt`, `reference/<case>/timing.json` (มนุษย์ทำเอง), `results/<case>/metric.json` (คำนวณเทียบ reference), `editable-subtitle-test-log.md` |

## Objective 4B — Expert Evaluation

| หัวข้อ | รายละเอียด |
|---|---|
| **จำนวนคน** | ขั้นต่ำ **2 คน** (Must do) แนะนำ **3 คน** (Should do — เริ่มคำนวณ inter-rater agreement ได้) |
| **คุณสมบัติ** | มีประสบการณ์ตัดต่อวิดีโอ หรือผู้เชี่ยวชาญในสาขาเนื้อหาของคลิปทดสอบ (เช่น การเงิน ถ้าใช้ V02) — ไม่จำเป็นต้องรู้เรื่อง AI |
| **ให้ทำอะไร** | ดูคลิปต้นฉบับ → ดูคลิปที่ระบบตัดแล้ว (ผลจาก Objective 1) → ให้คะแนนตาม rubric 4 มิติ (ความต่อเนื่อง, ความเป็นธรรมชาติของรอยตัด, การคงประเด็นสำคัญ, คุณภาพโดยรวม) สเกล 1-5 → เขียนความเห็นเปิด |
| **จำนวนคลิปต่อคน** | 2-3 คลิปจาก Objective 1 (เลือกตามเกณฑ์ตายตัว เช่น 1 คลิปที่ metric ดีที่สุด + 1 คลิปที่ metric กลาง ๆ — ไม่ใช่เลือกหลังเห็นผล) |
| **เวลา** | ~5-10 นาที/คลิป รวม ~15-30 นาที/คน |
| **วัดผลด้วยอะไร** | ค่าเฉลี่ย±SD ต่อมิติ, inter-rater agreement (ถ้า ≥3 คน), สรุปความเห็นเชิงคุณภาพ |

## Objective 4C — User Evaluation

| หัวข้อ | รายละเอียด |
|---|---|
| **จำนวนคน** | ขั้นต่ำ **5 คน** (Must do — มาตรฐาน usability pilot ขนาดเล็ก) แนะนำ **8-10 คน** (Should do) |
| **คุณสมบัติ** | กลุ่มเป้าหมายของระบบ (ผู้ผลิตคอนเทนต์/ครีเอเตอร์ หรือเคยตัดต่อวิดีโอมาบ้าง) |
| **Task ที่ต้องทำ** | อัปโหลดคลิปจริงผ่านหน้าเว็บ → รอประมวลผล → ดู preview → แก้ไข (ถ้าต้องการ) → เรนเดอร์ → ดูผลลัพธ์ |
| **วัดผลด้วยอะไร** | **Task completion time** (จับเวลาแยกแต่ละขั้น: อัปโหลด/รอประมวลผล/แก้ไข/เรนเดอร์) · **Task success rate** (สำเร็จครบ flow โดยไม่ต้องมีคนช่วยหรือไม่ — % ของผู้เข้าร่วม) · แบบสอบถามหลัง task: satisfaction + perceived control (Likert 1-5) · **SUS score ถ้า Test Plan ฉบับจริงกำหนดให้ใช้** (ยังไม่ยืนยัน — ถ้าไม่ระบุ ใช้แบบสอบถามสั้นแทนได้) |
| **Evidence ที่ต้องเก็บ** | เวลาที่ใช้ต่อขั้นต่อคน, แบบสอบถามที่กรอกแล้ว, บันทึกจุดที่ติดขัด (ถ้ามี) |

## Objective 4D — Manual vs AI-assisted

| หัวข้อ | รายละเอียด |
|---|---|
| **จำนวนคน** | ขั้นต่ำ **3 คน** (Must do — เห็นแนวโน้มได้แต่ยังไม่ใช่สถิติเต็มรูปแบบ ต้องระบุเป็นข้อจำกัดในรายงาน) แนะนำ **6 คนขึ้นไป** (Should do) |
| **Design** | Within-subject: คนเดียวกันทำทั้งสองแบบ คนละคลิป (ยากง่ายใกล้เคียงกัน) สลับลำดับระหว่างคน (counterbalance กันผล learning effect) |
| **คุณสมบัติ** | มีพื้นฐานตัดต่อวิดีโอ (ต้องทำฝั่ง manual ได้จริง) |
| **เปรียบเทียบด้วยตัวชี้วัดอะไร** | **เวลาที่ใช้** (manual vs AI-assisted, paired comparison) · **satisfaction/perceived control** เปรียบเทียบระหว่าง 2 วิธี (Likert 1-5 + คำถามเปิด "แบบไหนควบคุมได้มากกว่า เพราะอะไร") — **การตัดสินคุณภาพผลลัพธ์ให้คนเองหรือผู้เชี่ยวชาญ (4B) ประเมิน ไม่ใช่ Claude** |
| **Evidence ที่ต้องเก็บ** | ไฟล์ output ทั้ง 2 แบบต่อคน, เวลาที่ใช้ต่อรอบ, แบบสอบถาม |
