# Objective 3 — Data Setup (วิธีที่เร็วที่สุดที่ยังน่าเชื่อถือ)

- ส่วนขยายของ `objective3/PROTOCOL.md` (นิยาม 6 องค์ประกอบ) — ไฟล์นี้ตอบเฉพาะ "จะเลือกข้อมูลยังไงให้เร็วที่สุดโดยไม่ทำให้ผลเอนเอียง"
- **ห้ามสร้าง reference transcript ปลอม** — ไฟล์นี้เสนอ "จะเลือกอะไร" ไม่ใช่ "สร้างเฉลยแทนคน"

---

## เสนอ: ใช้คลิปย่อยจากชุด V02–V07 — ได้ ถ้าเลือกให้ถูกเหตุผล

### ข้อดี (เหตุผลที่ทำให้เร็วขึ้น)
- ไฟล์เสียง/วิดีโอ/Whisper transcript ดิบมีอยู่แล้วใน `backend/storage/` ไม่ต้องอัปโหลด/เตรียมข้อมูลใหม่
- ผลลัพธ์ (ซับที่ระบบสร้าง) จะมีอยู่แล้วจาก Objective 1 (ไม่ต้องรัน pipeline ซ้ำสำหรับ Objective 3 โดยเฉพาะ — ใช้ output เดิมได้เลย)
- คนถอดเสียงมีบริบทของคลิปอยู่แล้ว (ถ้าเป็นคนเดียวกับที่เขียน `ground_truth.txt` จะรู้จักเนื้อหาคลิปดี ลดเวลาทำความเข้าใจ)

### ความเสี่ยงที่ต้องระวัง (เหตุผลที่ต้องเลือกอย่างมีเงื่อนไข ไม่ใช่เลือกมั่ว)
1. **Bias จากการรู้ผลล่วงหน้า** — คนที่เคยเขียน `ground_truth.txt` (เฉลยว่า "ควรตัดตรงไหน") แล้วมาถอดเสียง reference transcript ของคลิปเดียวกันอาจถอด/กำกับเวลาโดยไม่ได้ตั้งใจให้เข้ากับสิ่งที่ตัวเองรู้อยู่แล้วว่าระบบจะตัดตรงไหน — **แก้โดย:** ถอดเสียงแบบ blind เท่าที่ทำได้ (ฟังจากไฟล์เสียงดิบ ไม่เปิดดูผลลัพธ์ของระบบหรือ `ground_truth.txt` ระหว่างถอด)
2. **คลิปที่ใช้วัด threshold ไปแล้วอาจไม่เป็นตัวแทนที่ดี** — V02–V07 ถูกใช้ทั้งหาเกณฑ์ (`VAD_PREFILTER_MIN_SPEECH`, `SILENCE_HINT_MIN_GAP`) และประเมินผลมาตลอด (overfitting risk ที่ Pre-Final Audit เคยระบุไว้แล้วในบริบทของ Objective 1) — สำหรับ Objective 3 (ความแม่นยำถอดเสียง/ซับ) ความเสี่ยงนี้ **น้อยกว่า** เพราะ subtitle accuracy ไม่ได้ผูกกับ threshold การตัดที่ถูกวัดมา (เป็นคนละ pipeline: Whisper→AI-Correction→srt_utils ไม่เกี่ยวกับ `filter_transcript_by_vad`/`_long_silence_gaps`) จึงใช้ V02–V07 สำหรับ Objective 3 ได้โดยความเสี่ยง overfitting ต่ำกว่ากรณี Objective 1 มาก

### ข้อเสนอที่เป็นรูปธรรม

| ขั้นต่ำ (Must do) | แนะนำ (Should do) |
|---|---|
| เลือก **2 คลิป** จาก V02–V07 | เลือก **3 คลิป** |
| เกณฑ์เลือก: 1 คลิปที่มีคำเฉพาะทาง/ชื่อเฉพาะเยอะ (เช่น V04 สัมภาษณ์ที่มีศัพท์เฉพาะ) + 1 คลิปที่มีคำพูดปกติทั่วไป (เช่น V02) — เพื่อให้เห็นทั้งกรณีง่ายและกรณียาก | เพิ่มคลิปที่มี AI-Correction ทำงานจริง (มีอักษรละตินปน — ตรวจได้จาก log `[AI-Correct]` ของรอบก่อน) เพื่อวัด corrected-text comparison ด้วย |
| คนถอด: ไม่จำเป็นต้องเป็นคนเดียวกับที่เขียน GT เดิม แต่ถ้าเป็นคนเดียวกันต้องถอดแบบ blind ตามข้อ 1 ด้านบน | ถ้าเป็นไปได้ ให้คนละคนกับที่เขียน GT เดิม เพื่อตัด bias ออกไปเลย |

### สิ่งที่ยัง "ไม่เร็วกว่า" ได้ — ต้องยอมรับ

- **การถอดเสียง + กำกับเวลาอ้างอิงยังต้องใช้เวลาคนจริงเสมอ** ไม่มีทางลัดที่ไม่ใช้คน (ห้าม Claude ถอดแทนหรือใช้ Whisper output เป็นเฉลยของตัวเอง — วัดอะไรไม่ได้จริง)
- ประมาณเวลา: คลิปยาว 2–3 นาที (เท่าที่เห็นในชุด V02–V07) ถอด+กำกับเวลาอย่างละเอียด ใช้เวลาราว **20–40 นาที/คลิป** สำหรับคนที่ทำงานนี้เป็นครั้งแรก (ประมาณการทั่วไป ไม่ใช่ตัวเลขที่วัดจริงในโปรเจกต์นี้ — ต้องปรับตามจริงหลัง pilot คลิปแรก)

---

## ขั้นตอนที่เสนอ (ลำดับที่เร็วที่สุด)

1. เลือก 2-3 คลิปตามเกณฑ์ข้างต้น (ทำได้ทันที ไม่ต้องรอใคร)
2. คนถอดเสียงฟังไฟล์เสียงดิบ (`backend/storage/<job>/full_audio.wav`) เขียน reference transcript + กำกับเวลาแบบ blind (ไม่ดูผลลัพธ์ระบบ/GT เดิม)
3. หลังถอดเสร็จ จึงเปิดดูซับที่ระบบสร้างจริง (จาก Objective 1 ที่รันคู่ขนานไปแล้ว) มาเทียบ
4. คำนวณ metric ตามที่ยืนยันจาก Test Plan ฉบับจริง (ดู `objective3/PROTOCOL.md` ข้อ 3)

**ข้อ 1-2 ทำคู่ขนานกับ Objective 1/2 Gemini run ได้เต็มที่ (ไม่ต้องรอ)** — ข้อ 3-4 ต้องรอผล Objective 1 ก่อน (ใช้ output เดียวกัน ไม่ต้องรัน pipeline ซ้ำ)

## ยืนยันอีกครั้ง
