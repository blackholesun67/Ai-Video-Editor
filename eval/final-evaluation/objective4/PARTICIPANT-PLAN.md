# Objective 4 — Participant Plan (B/C/D)

- ขยายจาก `objective4/PROTOCOL.md` — ไฟล์นี้เจาะจงตัวเลขผู้เข้าร่วม/task/เวลา/เครื่องมือวัดให้ชัดพอเริ่มหาคนได้จริง
- **ไม่พบจำนวนผู้เข้าร่วมที่ Test Plan ฉบับทางการกำหนดไว้** (ค้นแล้วใน `docs/REPORT_NOTES.md` และทั้ง repo — ไม่มีตัวเลขระบุ) จำนวนที่เสนอด้านล่างเป็น**คำแนะนำของ Claude ที่อ้างอิงมาตรฐานทั่วไปของ usability/expert-review pilot ขนาดเล็ก ไม่ใช่ตัวเลขจาก Test Plan** — **ต้องให้ผู้ใช้/อาจารย์ที่ปรึกษายืนยันก่อนใช้จริง** ถ้า Test Plan ฉบับจริงกำหนดจำนวนไว้ ให้ยึดตามนั้นแทนตัวเลขในไฟล์นี้ทันที
- **ห้ามใช้ Claude แทน participant ในทุกกรณี** (B/C/D) — Claude ทำได้แค่เตรียม protocol/รวบรวมผล ไม่ใช่ให้ความเห็น/คะแนนแทนคน

## B. Expert Evaluation

| หัวข้อ | รายละเอียด |
|---|---|
| **จำนวนผู้เข้าร่วม** | **ขั้นต่ำ 2 คน** (Must do) — แนะนำ 3 คน (Should do) เพื่อดู inter-rater agreement ได้แม่นขึ้น (2 คนเห็นแค่ agree/disagree แบบคู่ ; 3 คนขึ้นไปเริ่มคำนวณ agreement เป็นสัดส่วนได้) |
| **คุณสมบัติผู้เข้าร่วม** | ผู้มีประสบการณ์ตัดต่อวิดีโอ หรือผู้สอน/ผู้เชี่ยวชาญในสาขาเนื้อหาของคลิปทดสอบ (เช่น การเงิน/การลงทุน ถ้าใช้คลิป V02) — ไม่จำเป็นต้องเป็นผู้เชี่ยวชาญด้าน AI |
| **Task** | ดูคลิปต้นฉบับ 1 คลิป → ดูคลิปที่ระบบตัดแล้ว (ผลจาก Objective 1) → ให้คะแนนตาม rubric → เขียนความเห็นเปิด |
| **Rubric (ร่าง — ต้องยืนยัน/ปรับตาม Test Plan ถ้ามี)** | มิติ 4 ข้อ สเกล Likert 1–5: (1) ความต่อเนื่องของเนื้อหา (ไม่กระโดด) (2) ความเป็นธรรมชาติของรอยตัด (ไม่รู้สึกว่าถูกตัด) (3) การคงประเด็นสำคัญไว้ครบ (4) คุณภาพโดยรวมเทียบกับที่คาดหวังจากมืออาชีพ |
| **จำนวนคลิปต่อผู้เข้าร่วม** | 2-3 คลิปจาก Objective 1 (เลือกคลิปที่มีผลชัดเจน เช่น V07 ที่ Snap fix พิสูจน์แล้ว + 1 คลิปที่ recall/precision กลาง ๆ เพื่อดูความเห็นในกรณีที่ไม่ perfect) |
| **เวลา** | ~5–10 นาที/คลิป (ดูคลิปต้นฉบับ+คลิปตัดแล้ว+กรอกคะแนน) → รวม ~15–30 นาที/ผู้เข้าร่วม (2-3 คลิป) |
| **Evidence** | แบบประเมินที่กรอกแล้ว (กระดาษ/ฟอร์มออนไลน์) ต่อผู้เชี่ยวชาญต่อคลิป — เก็บที่ `eval/final-evaluation/objective4/results/expert/<participant_id>/<case>.json` |
| **Metric** | ค่าเฉลี่ย±SD ต่อมิติ, inter-rater agreement (ถ้า ≥3 คน), สรุปความเห็นเชิงคุณภาพแบบ thematic |

## C. User Evaluation

| หัวข้อ | รายละเอียด |
|---|---|
| **จำนวนผู้เข้าร่วม** | **ขั้นต่ำ 5 คน** (Must do — มาตรฐานทั่วไปของ usability pilot ขนาดเล็ก, Nielsen's rule-of-thumb ตรวจปัญหา usability ใหญ่ได้ส่วนใหญ่ด้วย n=5) แนะนำ **8-10 คน** (Should do) ถ้าต้องการค่าสถิติ satisfaction ที่มั่นใจขึ้น |
| **คุณสมบัติผู้เข้าร่วม** | กลุ่มเป้าหมายของระบบ (ผู้ผลิตคอนเทนต์/ครีเอเตอร์ หรือคนที่เคยตัดต่อวิดีโอมาบ้าง) — ไม่จำเป็นต้องเป็นมืออาชีพ |
| **Task** | อัปโหลดคลิปของตัวเอง (หรือคลิปตัวอย่างที่เตรียมไว้) ผ่านหน้าเว็บจริง → รอผล → ดู preview → แก้ไข (ถ้าต้องการ) → เรนเดอร์ → ดาวน์โหลด/ดูผลลัพธ์ |
| **Task success นิยาม** | ผู้ใช้ทำได้ครบ อัปโหลด→preview→render โดยไม่ต้องมีคนช่วยแทรกแซง (สำเร็จ/ไม่สำเร็จแบบ binary + บันทึกจุดที่ติดขัดถ้าไม่สำเร็จ) |
| **เวลา** | จับเวลาแยกแต่ละขั้น: อัปโหลด, รอประมวลผล (ระบบจับเองได้จาก log), แก้ไข, render — รวมเซสชันประมาณ 15-25 นาที/คน (ไม่รวมเวลารอประมวลผลที่ระบบทำเอง) |
| **Questionnaire** | หลัง task เสร็จ: (1) satisfaction โดยรวม (Likert 1-5) (2) perceived control ("รู้สึกว่าควบคุมผลลัพธ์ได้แค่ไหน" Likert 1-5) (3) ความยากง่ายของการใช้งาน (3) ความเห็นเปิด — **ถ้า Test Plan ฉบับจริงระบุให้ใช้ SUS (System Usability Scale) ให้ใช้ SUS มาตรฐาน 10 ข้อแทนแบบสอบถามสั้นนี้** (ยังไม่ยืนยันจาก Test Plan) |
| **Evidence** | เวลาที่ใช้ต่อขั้น, แบบสอบถามที่กรอกแล้ว, บันทึกจุดที่ติดขัด (ถ้ามี) — เก็บที่ `eval/final-evaluation/objective4/results/user/<participant_id>/` |
| **Metric** | task success rate (% ของผู้เข้าร่วมที่สำเร็จ), task time เฉลี่ย±SD ต่อขั้น, คะแนนแบบสอบถามเฉลี่ย±SD |

## D. Manual vs AI-assisted

| หัวข้อ | รายละเอียด |
|---|---|
| **จำนวนผู้เข้าร่วม** | **ขั้นต่ำ 3 คน** (Must do — เห็นแนวโน้มได้แต่ยังไม่ใช่สถิติเต็มรูปแบบ ต้องระบุเป็นข้อจำกัดตรง ๆ ในรายงาน) แนะนำ **6 คนขึ้นไป** (Should do) ถ้าเวลา/ทรัพยากรพอ |
| **Design** | **Within-subject แนะนำ**: คนเดียวกันทำทั้ง manual และ AI-assisted แต่ใช้คลิปคนละคลิป (ยากง่ายใกล้เคียงกัน) สลับลำดับระหว่างผู้เข้าร่วม (counterbalancing — ครึ่งหนึ่งทำ manual ก่อน อีกครึ่งทำ AI-assisted ก่อน) เพื่อกันผลกระทบจากการเรียนรู้ (learning effect) |
| **คุณสมบัติผู้เข้าร่วม** | มีประสบการณ์ตัดต่อวิดีโอพื้นฐาน (ต้องทำฝั่ง manual ได้จริงในเวลาที่กำหนด) |
| **Task** | ตัดคลิปตามโจทย์เดียวกัน (เช่น "ตัดช่วงเงียบ/พูดผิด/คำติดปากออก") ด้วย (1) โปรแกรมตัดต่อทั่วไปที่ผู้เข้าร่วมถนัด (2) ระบบนี้ แล้วปรับแต่งผลที่ได้ต่อ |
| **เวลา** | จับเวลารวมของแต่ละรอบ (ไม่จำกัดเวลาสูงสุดตายตัว แต่ตั้ง soft cap ไว้ล่วงหน้า เช่น 20 นาที/รอบ กันคนหมดแรงจนข้อมูลเพี้ยน) |
| **Questionnaire** | หลังทำครบทั้ง 2 รอบ: เปรียบเทียบ perceived control และ satisfaction ระหว่าง 2 วิธี (Likert 1-5 ต่อวิธี + คำถามเปิด "แบบไหนรู้สึกควบคุมได้มากกว่า เพราะอะไร") |
| **Evidence** | ไฟล์ output ทั้ง 2 แบบต่อผู้เข้าร่วม, เวลาที่ใช้ต่อรอบ, แบบสอบถาม — เก็บที่ `eval/final-evaluation/objective4/results/manual-vs-ai/<participant_id>/` |
| **Metric** | task time (manual vs AI-assisted, paired comparison), satisfaction/perceived-control เปรียบเทียบ — **การตัดสิน "คุณภาพ" ผลลัพธ์ให้ผู้เข้าร่วมเอง หรือส่งต่อให้ผู้เชี่ยวชาญ (ส่วน B) ประเมิน ไม่ใช่ Claude ตัดสิน** |

## สรุปจำนวนที่ต้องหา (Must do ขั้นต่ำรวม)

| ส่วน | จำนวนขั้นต่ำ | หมายเหตุ |
|---|---|---|
| B. Expert | 2 คน | อาจซ้ำกับ D ได้ถ้าผู้เชี่ยวชาญสะดวกทำทั้งสองส่วน (ประหยัดเวลาหาคน) |
| C. User | 5 คน | ควรเป็นคนละกลุ่มกับ B (มุมมองผู้ใช้ทั่วไป ไม่ใช่ผู้เชี่ยวชาญ) |
| D. Manual vs AI-assisted | 3 คน | ต้องมีพื้นฐานตัดต่อ — อาจทับซ้อนกับ C บางส่วนถ้าผู้เข้าร่วมมีพื้นฐานพอ |
| **รวมต่ำสุด (ถ้าไม่ overlap เลย)** | **10 คน** | ถ้าจัดให้บางคนทำได้มากกว่า 1 ส่วน อาจลดจำนวนคนจริงที่ต้องหาได้ (แต่ต้องระบุไว้ชัดว่าใครทำกี่ส่วน เพื่อไม่ให้ผลปนกันโดยไม่รู้ตัว) |

## ข้อควรระวังเรื่อง bias

- ผู้เข้าร่วม C/D **ไม่ควรเป็นคนที่มีส่วนพัฒนาระบบ** (ผู้ใช้เอง/Claude ไม่นับเป็น participant อยู่แล้ว แต่ถ้ามีผู้ร่วมพัฒนาคนอื่นต้องเลี่ยง)
- ถ้าผู้เชี่ยวชาญ (B) เห็นผลลัพธ์จาก Objective 1 ที่ "คัดมาแล้ว" (เลือกเฉพาะเคสที่ดี) จะเกิด selection bias — **ต้องเลือกคลิปให้ผู้เชี่ยวชาญดูตามเกณฑ์ที่ตั้งไว้ล่วงหน้า** (เช่น "1 เคสที่ metric ดีที่สุด + 1 เคสที่ metric กลาง ๆ") ไม่ใช่เลือกหลังเห็นผลว่าอันไหนดูดี
