## B. Expert Evaluation

| หัวข้อ | รายละเอียด |
|---|---|
| **จำนวนผู้เข้าร่วม** | **3 ท่าน** (ผู้ใช้กำหนด) — เกณฑ์เดิมที่เคยร่างไว้คือขั้นต่ำ 2 / แนะนำ 3 |
| **คุณสมบัติผู้เข้าร่วม** | ผู้มีประสบการณ์ตัดต่อวิดีโอ หรือผู้สอน/ผู้เชี่ยวชาญในสาขาเนื้อหาของคลิปทดสอบ — ไม่จำเป็นต้องเป็นผู้เชี่ยวชาญด้าน AI |
| **จำนวนคลิปต่อผู้เข้าร่วม / โหมด** | **2 คลิป** (ผู้ใช้กำหนด): ไฟล์ **B1** ด้วยโหมด **"เก็บเนื้อหาครบ"** และไฟล์ **C** ด้วยโหมด **"สรุปให้เข้าใจครบ"** → รวม 3 × 2 = **6 ชุดแบบประเมิน** |
| **Task (ลำดับที่ผู้ใช้กำหนด 2026-10-06)** | **ผู้เชี่ยวชาญรันระบบเอง 2 งานต่อท่าน ไม่ต้องอัปโหลดซ้ำ:** (1) อัปโหลดไฟล์ **B1** โหมด **"เก็บเนื้อหาครบ"** → รอผล → **เรนเดอร์ตามข้อเสนอของระบบโดยไม่แก้** (หน้าเลือกช่วงกด "ถัดไป" → หน้าแก้ซับกด "บันทึก" โดยไม่แก้) → ดูผลและตอบ **ส่วน ก** ของไฟล์ B1 (2) อัปโหลดไฟล์ **C** โหมด **"สรุปให้เข้าใจครบ"** → เรนเดอร์ตามข้อเสนอของระบบแบบเดียวกัน → ตอบ **ส่วน ก** ของไฟล์ C (3) ที่**หน้าผลลัพธ์ของไฟล์ C** กด **"แก้ช่วงตัด"** → ปรับช่วงตัด **1 จุด** → "ถัดไป" → แก้คำบรรยาย **1 บรรทัด** → "บันทึก" (เรนเดอร์ใหม่) → ดูผลและตอบ **ส่วน ข** — เรนเดอร์ใหม่ใช้ข้อมูลเดิมของงาน ไม่เรียก Gemini ซ้ำ จึงเรียก Gemini 2 ครั้งต่อท่าน (รวม 6 ครั้งสำหรับ 3 ท่าน ไม่นับการลองใหม่เมื่อโควตาเต็ม) |
| **Rubric (ร่าง — ต้องยืนยัน/ปรับตาม Test Plan ถ้ามี)** | มิติ 4 ข้อ สเกล Likert 1–5: (1) ความต่อเนื่องของเนื้อหา (ไม่กระโดด) (2) ความเป็นธรรมชาติของรอยตัด (ไม่รู้สึกว่าถูกตัด) (3) การคงประเด็นสำคัญไว้ครบ (4) คุณภาพโดยรวมเทียบกับที่คาดหวังจากมืออาชีพ |
| **เวลา** | ~5–10 นาที/คลิป สำหรับการดูและให้คะแนน (ยังไม่ยืนยันจาก pilot) → ~10–20 นาที/ผู้เชี่ยวชาญ (2 คลิป) **ยังไม่รวมเวลาประมวลผลของระบบ** เพราะผู้เชี่ยวชาญรันเอง (ยังไม่ได้ประมาณ) |
| **Evidence** | แบบประเมินที่กรอกแล้วต่อผู้เชี่ยวชาญต่อคลิป — เก็บที่ `eval/final-evaluation/objective4/results/expert/<participant_id>/<case>.json` |
| **Metric** | **ค่าเฉลี่ย + ช่วงต่ำสุด–สูงสุด** ของคะแนนต่อมิติ (ต่อคลิป), สรุปความเห็นเชิงคุณภาพแบบ thematic |

**การรายงานคะแนน:** ใช้ค่าเฉลี่ย + ช่วงต่ำสุด–สูงสุดของ 3 ท่านต่อมิติต่อคลิป — **ไม่รายงานค่าความสอดคล้องระหว่างผู้ประเมิน** เพราะแต่ละท่านรันระบบเอง ผลตัดที่แต่ละท่านประเมินจึงต่างกัน (ไม่ใช่การให้คะแนนผลชุดเดียวกัน) ; n = 3 ต่อคลิป จึงรายงานเชิงพรรณนาเท่านั้น

**⚠️ ยังไม่ยืนยัน:**
1. เนื้อหาของ **ส่วน ก / ส่วน ข** ของแบบประเมิน ยังไม่ได้กำหนดในไฟล์นี้ (rubric 4 มิติด้านบนเป็นร่าง — ต้องยืนยันว่าอยู่ส่วนไหน) ; ขั้น (3) ใช้ปุ่ม "แก้ช่วงตัด" บนหน้าผลลัพธ์ (commit `0ec563a`) — **ยังไม่ได้ลองในเบราว์เซอร์จริงหลัง rebuild**
2. ไฟล์ B1 และ C ยังไม่อยู่ใน repo (ผู้ใช้ระบุเพียงชื่อ) ยังไม่ได้ตรวจความยาว/ขนาด — ถ้าเข้าผ่านโดเมน Cloudflare ไฟล์ต้องไม่เกิน 100 MB ; การเลือกไฟล์ต้องใช้เกณฑ์ที่ตั้งไว้ล่วงหน้า (ดูหัวข้อ bias)
3. เวลาที่ผู้เชี่ยวชาญต้องรอประมวลผลต่อไฟล์ ยังไม่ได้ประมาณสำหรับไฟล์ B1/C (ระบบประมวลผลทีละงาน — งานอื่นอาจต้องรอคิว)

| **คุณสมบัติผู้เข้าร่วม** | กลุ่มเป้าหมายของระบบ (ผู้ผลิตคอนเทนต์/ครีเอเตอร์ หรือคนที่เคยตัดต่อวิดีโอมาบ้าง) — ไม่จำเป็นต้องเป็นมืออาชีพ |

**⚠️ ยังไม่ยืนยัน:** ทุกคนใช้คลิปเดียวกันหรือคลิปของตัวเอง (มีผลต่อการเทียบเวลา task)

## D. Manual vs AI-assisted

| หัวข้อ | รายละเอียด |
|---|---|
| **จำนวนผู้เข้าร่วม** | **เพื่อน 4 คน** (ผู้ใช้กำหนด) — ต่ำกว่า "แนะนำ 6 คนขึ้นไป" ที่เคยร่างไว้ และเท่ากับจำนวนช่องของ design 2×2 พอดี (ช่องละ 1 คน) ต้องระบุเป็นข้อจำกัดตรง ๆ ในรายงาน |
| **Design (2×2)** | Within-subject crossover: วิธี (manual / AI-assisted) × คลิป (A / B) โดยคนเดียวทำทั้งสองวิธีบนคนละคลิป และสลับลำดับระหว่างคน — ตารางข้างล่าง |
| **คุณสมบัติผู้เข้าร่วม** | มีประสบการณ์ตัดต่อวิดีโอพื้นฐาน (ต้องทำฝั่ง manual ได้จริงในเวลาที่กำหนด) |
| **Task** | ตัดคลิปตามโจทย์เดียวกัน (เช่น "ตัดช่วงเงียบ/พูดผิด/คำติดปากออก") ด้วย (1) โปรแกรมตัดต่อทั่วไปที่ผู้เข้าร่วมถนัด (2) ระบบนี้ แล้วปรับแต่งผลที่ได้ต่อ |
| **งานที่ต้องการ "ไม่ตัดอะไร"** | งาน A ของ 4D (และงาน CER/WER) ใช้ โหมด "เก็บเนื้อหาครบ" + กดปุ่ม "เลือกทั้งหมด" ในหน้า preview (ไม่มีโหมดแยกสำหรับ "ไม่ตัดอะไร" — ระบบยังวิเคราะห์ตามปกติ แล้วปุ่มนี้ติ๊กเก็บทุกช่วงรวมช่วงที่ AI เสนอตัด) ; ตรวจแล้ว 1 ตัวอย่าง (วิดีโอ 16:9 ยาว 144.406 s, เบิร์นซับ): payload จากการเลือกทั้งหมดเป็นช่วงเดียว 0–144.4 s และไฟล์ที่เรนเดอร์ยาว 144.382 s (ต่างจากต้นฉบับ 0.024 s) — หน้าเว็บปัดเวลาที่ 0.1 s จึงอาจขาดท้ายคลิปได้ไม่เกินราว 0.05 s ; ยังไม่ได้ตรวจกับไฟล์ B1/C และ 4D จริง |
| **เวลา** | จับเวลารวมของแต่ละรอบ (ตั้ง soft cap ไว้ล่วงหน้า เช่น 20 นาที/รอบ — ยังไม่ยืนยัน) |
| **Questionnaire** | หลังทำครบทั้ง 2 รอบ: เปรียบเทียบ perceived control และ satisfaction ระหว่าง 2 วิธี (Likert 1–5 ต่อวิธี + คำถามเปิด "แบบไหนรู้สึกควบคุมได้มากกว่า เพราะอะไร") |
| **Evidence** | ไฟล์ output ทั้ง 2 แบบต่อผู้เข้าร่วม, เวลาที่ใช้ต่อรอบ, แบบสอบถาม — เก็บที่ `eval/final-evaluation/objective4/results/manual-vs-ai/<participant_id>/` |
| **Metric** | task time (manual vs AI-assisted, ผลต่างต่อคน), satisfaction/perceived-control เปรียบเทียบ — รายงานเป็น **รายบุคคล + เชิงพรรณนา** ไม่ทำสถิติอนุมาน (n = 4) ; **การตัดสิน "คุณภาพ" ให้ผู้เข้าร่วมเองหรือส่งต่อให้ผู้เชี่ยวชาญ (ส่วน B) ประเมิน ไม่ใช่ Claude ตัดสิน** |

**ตาราง 2×2 (การตีความของ Claude — ดูข้อสงสัยข้างล่าง):**

| ผู้เข้าร่วม | รอบที่ 1 | รอบที่ 2 |
|---|---|---|
| เพื่อน 1 | Manual บนคลิป A | AI-assisted บนคลิป B |
| เพื่อน 2 | Manual บนคลิป B | AI-assisted บนคลิป A |
| เพื่อน 3 | AI-assisted บนคลิป A | Manual บนคลิป B |
| เพื่อน 4 | AI-assisted บนคลิป B | Manual บนคลิป A |

ผลของการจัดแบบนี้: แต่ละวิธีถูกทำบนทั้งคลิป A และ B อย่างละ 2 ครั้ง และแต่ละวิธีอยู่รอบที่ 1 / รอบที่ 2 อย่างละ 2 ครั้ง จึงแยกผลของ "วิธี" ออกจาก "ความยากของคลิป" และ "ลำดับ (learning effect)" ได้ในระดับเชิงพรรณนา

**⚠️ ยังไม่ยืนยัน:**
1. ความหมายของ "2×2" — ตีความข้างบนว่าเป็น วิธี × คลิป ; ถ้าหมายถึงอย่างอื่น (เช่น วิธี × ลำดับเท่านั้น) ต้องแก้ตาราง
2. คลิป A/B ยังไม่ระบุ (ผู้ใช้แจ้งว่าคลิปทดสอบ 4D จะถูกเปลี่ยน) ; ต้องยากง่ายใกล้เคียงกัน
3. เพื่อนทั้ง 4 คนอาจให้คะแนนความพึงพอใจสูงกว่าความจริงเพราะเกรงใจ — ดูหัวข้อ bias

## ข้อควรระวังเรื่อง bias

- ผู้เข้าร่วม C/D **ไม่ควรเป็นคนที่มีส่วนพัฒนาระบบ** (ผู้ใช้เอง/Claude ไม่นับเป็น participant อยู่แล้ว แต่ถ้ามีผู้ร่วมพัฒนาคนอื่นต้องเลี่ยง)
- การเลือกไฟล์ B1 และ C ให้ผู้เชี่ยวชาญ (B) ต้องใช้เกณฑ์ที่ตั้งไว้ล่วงหน้า (เช่น "1 ไฟล์ที่ metric ดี + 1 ไฟล์ที่ metric กลาง ๆ") ไม่ใช่เลือกหลังเห็นผลว่าอันไหนดูดี — มิฉะนั้นเกิด selection bias
- **เพื่อน (D):** อาจเกรงใจจนให้คะแนนความพึงพอใจสูงเกินจริง (social desirability) — ควรเน้นตัวชี้วัดที่วัดได้ (เวลา, ผลลัพธ์) มากกว่าความเห็น และระบุเป็นข้อจำกัดในรายงาน
