# Objective 4 — Functional + Human

**ห้ามใช้ Claude แทนผู้เข้าร่วม (participant) จริงในส่วน B/C/D — บันทึกไว้ชัดเจนที่นี่ตามที่กำหนด**

## A. Functional Test — script/Claude ทดสอบได้เอง

### สถานะ: NOT READY (เล็กน้อย — เตรียมได้เองโดยไม่ต้องใช้คน)

evidence ที่มีอยู่จากทั้ง 3 fixes จำกัดอยู่ที่ `analyze_video_content()` เรียกตรง (ผ่าน `analysis_harness.py`) ไม่เคยผ่าน endpoint จริงของ FastAPI/Celery เลย

| Task | รายละเอียด | Evidence ที่ต้องการ |
|---|---|---|
| Upload → process (`POST` อัปโหลด → `process_video_task`) | เรียก endpoint จริงด้วย `requests`/`httpx` ส่งไฟล์วิดีโอตัวอย่าง 1 ไฟล์ ตรวจว่า job ถูกสร้างและ Celery task ทำงานจนจบ | log/response ของ endpoint, สถานะ job สุดท้าย |
| `GET/POST /subtitle` | ตรวจว่า endpoint คืนค่า segments ที่ถูกต้องตรงกับที่ `POST` ไปล่าสุด (CLAUDE.md §2.5 — ต้องใช้ `POST /subtitle/{job_id}` ไม่ใช่ `GET` เป็นค่าหลัก) | response body เทียบ payload ที่ส่งไป |
| `render_only_task` | เรียก render ด้วย segments ที่แก้ไขแล้ว ตรวจว่าไฟล์ output ตรงตามที่เลือก (ความยาว/จำนวนช่วง) | ไฟล์ video output + log |
| Preview/Edit selection UI (`PreviewScreen.jsx`) | ทดสอบตรรกะ pure function ผ่าน `useTimelineRows.js` ได้ด้วย `npx esbuild` ตามที่ CLAUDE.md §7 ระบุไว้แล้ว (มีอยู่แล้ว ไม่ต้องสร้างใหม่) — ส่วนนี้ **script ทดสอบได้เต็มที่** | ผลรัน esbuild test |

**Procedure:** ใช้คลิปตัวอย่าง 1–2 คลิปจากชุด V02–V07 ยิง endpoint จริงผ่าน `docker compose` ที่รันอยู่ (ผู้ใช้เป็นคนสั่ง `docker compose up` ตามข้อตกลงเดิม — CLAUDE.md §7) แล้ว Claude ตรวจผลจาก response/log

**Metric:** pass/fail ต่อ endpoint, response time, ความถูกต้องของ output เทียบ input ที่ส่งไป — ไม่ใช่ recall/precision (นั่นเป็นของ Objective 1)

## B. Expert Evaluation — ต้องใช้คนจริง

### สถานะ: NOT SET UP

| หัวข้อ | รายละเอียด |
|---|---|
| Participant requirements | ผู้เชี่ยวชาญด้านการตัดต่อวิดีโอ หรือผู้สอน/ผู้เชี่ยวชาญในสาขาที่เกี่ยวข้องกับเนื้อหาคลิปทดสอบ — จำนวนแนะนำ ≥2 คน (เพื่อดู inter-rater agreement เบื้องต้น) |
| Task | ให้ผู้เชี่ยวชาญดูผลลัพธ์จาก Objective 1 (คลิปเดิม, ผลตัดจากระบบ) แล้วประเมินคุณภาพตาม rubric |
| Rubric | **ยังไม่ได้ออกแบบ** — ต้องกำหนดมิติการประเมิน (เช่น ความต่อเนื่องของเนื้อหา, ความเป็นธรรมชาติของรอยตัด, การคงประเด็นสำคัญ) พร้อมสเกล (เช่น Likert 1–5) ก่อนเริ่ม |
| Procedure | ร่าง: (1) ดูคลิปต้นฉบับ (2) ดูคลิปที่ระบบตัดแล้ว (3) ให้คะแนนตาม rubric (4) เขียนความเห็นเปิด (open-ended) |
| Timing | ประมาณ 5–10 นาทีต่อคลิป (ต้องยืนยันจริงตอนนำร่อง/pilot) |
| Evidence | แบบประเมินที่กรอกแล้วต่อผู้เชี่ยวชาญต่อคลิป |
| Metric | ค่าเฉลี่ยคะแนนต่อมิติ, ความเห็นเชิงคุณภาพ |

**สิ่งที่ต้องเตรียม:** ออกแบบ rubric, หาผู้เชี่ยวชาญ ≥2 คน, เตรียมคลิปตัวอย่างที่ตัดแล้วจาก Objective 1

## C. User Evaluation — ต้องใช้คนจริง

### สถานะ: NOT SET UP

| หัวข้อ | รายละเอียด |
|---|---|
| Participant requirements | ผู้ใช้ทั่วไปที่เป็นกลุ่มเป้าหมายของระบบ (เช่น ผู้ผลิตคอนเทนต์/ครีเอเตอร์) — จำนวนตาม Test Plan ฉบับจริงกำหนด (ไม่พบในเอกสารที่มีอยู่ใน repo ต้องยืนยันจากภายนอก) |
| Task | ให้ผู้ใช้ทดลองใช้ระบบจริงตั้งแต่อัปโหลดจนได้ผลลัพธ์ (ผ่านหน้าเว็บจริง ไม่ใช่ script) |
| Task success | นิยามว่า "สำเร็จ" คืออะไร (เช่น อัปโหลด→preview→แก้ไข→render ได้ครบโดยไม่ต้องความช่วยเหลือ) — ต้องกำหนดก่อนเริ่ม |
| Task time | จับเวลาแต่ละขั้น (อัปโหลด, รอประมวลผล, แก้ไข, render) |
| Questionnaire | แบบสอบถามความพึงพอใจ/การรับรู้การควบคุม (perceived control) — ใช้ **SUS (System Usability Scale)** ถ้า Test Plan ฉบับจริงกำหนดไว้ (ยืนยันจากเอกสารภายนอกก่อน ไม่ยืนยันเองในเอกสารนี้) |
| Evidence | บันทึกเวลา, แบบสอบถามที่กรอกแล้ว, บันทึกการสังเกต (ถ้ามี) |
| Metric | task success rate, task time, คะแนนแบบสอบถาม (satisfaction/perceived control/SUS) |

**สิ่งที่ต้องเตรียม:** นิยาม task success ที่ชัดเจน, แบบสอบถามมาตรฐาน (ยืนยัน SUS หรือแบบอื่นจาก Test Plan), หาผู้เข้าร่วม, เตรียมสภาพแวดล้อมทดสอบ (ระบบต้องรันอยู่ ผู้ใช้ทดสอบเป็นคนสั่งเอง)

## D. Manual vs AI-assisted — ต้องใช้คนจริงทั้งสองฝั่ง

### สถานะ: NOT SET UP

| หัวข้อ | รายละเอียด |
|---|---|
| Task | ให้ผู้เข้าร่วมตัดคลิปเดียวกัน 2 แบบ: (1) ตัดเองล้วน ๆ ด้วยโปรแกรมตัดต่อทั่วไป (2) ใช้ระบบนี้ช่วย แล้วปรับแต่งต่อ |
| Participant requirements | แนะนำ within-subject design (คนเดียวกันทำทั้ง 2 แบบ คนละคลิป สลับลำดับกันกันผลกระทบจากการเรียนรู้) หรือ between-subject ถ้าหาคนได้มากพอ |
| Procedure | ร่าง: (1) อธิบายงาน (2) จับเวลา manual (3) จับเวลา AI-assisted (4) เก็บผลลัพธ์ทั้งสองแบบ (5) แบบสอบถามเปรียบเทียบ |
| Timing | จับเวลารวมของแต่ละแบบ |
| Questionnaire | เปรียบเทียบ perceived control / satisfaction ระหว่าง 2 แบบ |
| Evidence | ไฟล์ output ทั้ง 2 แบบต่อผู้เข้าร่วม, เวลาที่ใช้, แบบสอบถาม |
| Metric | task time (manual vs AI-assisted), task success, satisfaction เปรียบเทียบ — **ห้ามใช้ Claude ตัดสินว่าแบบไหน "ดีกว่า"** ต้องเป็นการประเมินของผู้เข้าร่วมเองหรือผู้เชี่ยวชาญ (ส่วน B) เท่านั้น |

**สิ่งที่ต้องเตรียม:** ออกแบบ within/between-subject, หาผู้เข้าร่วม, เตรียมโปรแกรมตัดต่อสำหรับฝั่ง manual, เตรียมคลิปที่ยากง่ายใกล้เคียงกันสำหรับสองรอบ

## สรุปการแยกงาน

| ส่วน | ใครทำ | พร้อมแค่ไหน |
|---|---|---|
| A. Functional | Claude/script | เตรียมได้ทันที ไม่ต้องรอคน |
| B. Expert evaluation | คนจริง (ผู้เชี่ยวชาญ) | ต้องออกแบบ rubric + หาคนก่อน |
| C. User evaluation | คนจริง (ผู้ใช้ทั่วไป) | ต้องออกแบบ questionnaire + หาคนก่อน |
| D. Manual vs AI-assisted | คนจริงทั้งสองฝั่ง | ต้องออกแบบ procedure + หาคนก่อน |

**Claude ไม่ควรทำ B/C/D แทนคนไม่ว่าในรูปแบบใด** (รวมถึงการ "จำลอง" ความเห็นผู้ใช้หรือให้คะแนนแทน) — เป็นหลักการที่ผู้ใช้กำชับไว้ตั้งแต่รอบ Pre-Final Audit และย้ำอีกครั้งในรอบนี้
