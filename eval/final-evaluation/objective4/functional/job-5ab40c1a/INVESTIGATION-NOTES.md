## ⚠️ พบหลักฐานสำคัญที่ทำให้ทิศทางการสืบสาเหตุเปลี่ยน

log บรรทัดที่มองข้ามไปตอนแรก:
```
⚡ [Cache HIT] transcript loaded for hash=5909864efe5691c3 (2 segments)
```

**transcript ที่ใช้ใน job นี้ไม่ได้ถอดสดจาก Whisper — โหลดมาจาก `transcript_cache` ที่ผูกกับ SHA-256 ของไฟล์เสียง (ตามที่ CLAUDE.md §4 อธิบายไว้)** เพราะไฟล์เสียงตรงกับ hash ที่เคยประมวลผลมาก่อน (ไบต์เดียวกับที่ใช้ตอน job แรกของวันนี้ `95a30f6c`) ระบบจึง**ข้าม Whisper ทั้งหมด**และหยิบผลเก่ามาใช้ตรง ๆ — ผลเก่านั้นคือ "2 segments, 2 chars" ที่ผิดปกติ

**แปลว่าปัญหาไม่ได้เกิดจาก VAD และไม่ได้เกิดใหม่ใน job นี้** — มันเกิดขึ้นครั้งเดียวตอน **job แรก (`95a30f6c`)** ตอนนั้น Whisper ถอดเสียงสดจริง (เพราะยังไม่มี cache) แล้วได้ผลเกือบว่างเปล่า (2 ตัวอักษร) จากนั้นค่านี้ถูกแคชไว้ และ job ที่สองก็ดึง cache เดิมมาใช้ซ้ำ — ยืนยันด้วยการค้นหา `docker compose logs --since=3h` ทั่วทั้ง log ไม่พบบรรทัด "Cache HIT" อื่นเลยนอกจากบรรทัดนี้บรรทัดเดียว (แปลว่า job แรกคือจุดที่สร้างค่านี้ขึ้นมา)

**ข้อสังเกตสำคัญ:** นี่เป็น**ครั้งแรกในการทดสอบทั้งวันนี้**ที่มีการถอดเสียงสดด้วย Whisper ผ่าน pipeline จริง — ทุกการรัน Objective 1/2 ก่อนหน้านี้ (`analysis_harness.py`) **ฉีด transcript จากไฟล์ baseline เดิมโดยตรง ไม่เคยเรียก Whisper ใหม่เลย** จึงไม่มีทางที่ปัญหานี้จะโผล่มาให้เห็นจากการทดสอบ Objective 1/2 ที่ผ่านมา — เป็นเส้นทางของโค้ดที่เพิ่งถูกใช้งานจริงเป็นครั้งแรกในรอบการทดสอบนี้

## 3. เทียบกับความแกว่งของ recall ใน Objective 2 (V02/V04) — ข้อสังเกต ไม่ฟันธง

| ประเด็น | เหตุการณ์นี้ (job `95a30f6c`→`5ab40c1a`) | Objective 2 (V02_full, V04_full recall 0%↔50%+) |
|---|---|---|
| จุดที่แปรปรวน | **ขั้น Whisper transcription** (input ที่ส่งให้ Gemini ผิดปกติตั้งแต่ต้น — "2 chars") | **ขั้นการตัดสินใจของ Gemini** (input/transcript ถูกต้องสมบูรณ์เหมือนกันทุกรอบ เพราะฉีดจาก baseline คงที่ — Gemini เองเลือกตัด/ไม่ตัดต่างกัน) |
| ลักษณะผลลัพธ์ที่เห็น | cuts=ทั้งคลิป (เพราะ Gemini เข้าใจถูกว่า input ที่ได้รับ "ไม่มีเสียงพูดเลย") → ระบบปฏิเสธเพราะ keep=0 | cuts=[] (Gemini เลือกไม่ตัดอะไรเลยจาก input ที่ถูกต้อง) หรือ cuts ถูกต้องบางส่วน |
| ความเหมือนผิวเผิน | ทั้งคู่จบด้วยตัวเลขสุดโต่ง (recall 0% หรือระบบล้มเหลว) ทำให้ถ้าดูแค่ metric ปลายทางอาจดูเหมือนเป็นปรากฏการณ์เดียวกัน | |
| ความต่างที่แท้จริง | เป็นปัญหา **คุณภาพ input** (transcript เพี้ยน) ซึ่งเป็นคนละชั้นกับ **ความแปรปรวนของการตัดสินใจ AI** ที่พบใน Objective 1/2 — ถ้า input ของเหตุการณ์นี้สมบูรณ์เหมือนที่ Objective 1/2 ใช้ ก็ไม่มีเหตุผลให้เชื่อว่าจะเกิดผลแบบเดียวกัน | |

**ข้อสังเกต (ไม่สรุปฟันธง):** เหตุการณ์นี้น่าจะเป็น**คนละสาเหตุ**กับความแกว่งของ recall ที่พบใน Objective 2 — Objective 2's variability เกิดที่ชั้น Gemini decision-making บน input ที่สมบูรณ์เหมือนกันทุกรอบ ส่วนเหตุการณ์นี้เกิดที่ชั้น Whisper transcription (input เสียก่อนถึง Gemini) ซึ่งไม่เคยถูกทดสอบมาก่อนในรอบนี้เลย **แต่ยังไม่มีหลักฐานเพียงพอจะฟันธง** ว่า Whisper transcription เองมีปัญหาความแปรปรวนแบบเดียวกับที่ Gemini มีหรือไม่ (n=1 เหตุการณ์เท่านั้น) — ต้องมีการรันซ้ำแบบ cold-cache (ไม่ใช้ cache, บังคับถอดใหม่) หลายรอบเพื่อตรวจว่า Whisper เองก็แปรปรวนได้เหมือน Gemini หรือเป็นเหตุการณ์เฉพาะครั้งเดียว — **เป็นข้อค้นพบใหม่ที่ต้องสืบสาเหตุเพิ่มเติมนอกรอบนี้**
