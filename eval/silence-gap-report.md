## 1. Problem

ช่วงเงียบที่อยู่ **ภายใน** transcript segment เดียวกันไม่ถูกส่งต่อเข้าสู่ขั้นตัดสินใจ ตัวอย่างจริง:

| คลิป | segment | ช่วงเงียบภายใน segment | hint ช่วงเงียบเดิมที่ Gemini ได้รับ |
|---|---|---|---|
| V02 | 34.4–65.4 | 47.4–51.6 (4.2 วิ) | ไม่มี (ว่าง) |
| V02 | 68.0–94.9 | 84.4–90.2 (5.8 วิ) | ไม่มี (ว่าง) |
| V07 | 0.0–52.6 | 16.8–31.6 (14.8 วิ) และ 37.0–49.2 (12.2 วิ) | ไม่มี (ว่าง) |
| V07 | 55.1–94.9 | 62.9–82.6 (19.7 วิ) | ไม่มี (ว่าง) |

## 2. Root Cause (ยืนยันจากโค้ดจริง ไม่ใช่จาก log)

1. **`get_silence_gaps()` ไม่ถูกเรียกใช้เลย** — นิยามอยู่ที่ [vad_logic.py:108](../backend/core/vad_logic.py#L108) ค้นทั้ง repo ที่ tag `vad-fix-v1` ได้ 0 จุดเรียกใช้ (`git grep`) มันคำนวณช่วงเงียบระหว่าง `voice_segments` ได้ตรงตัว แต่ไม่มีที่ใดนำไปใช้
2. **hint ช่วงเงียบวัดจากแหล่งเดียว:** `_long_silence_gaps(transcript, total_duration)` (ที่ `vad-fix-v1` บรรทัด 964, เรียกที่บรรทัด 2359) คำนวณจาก "ช่องว่างระหว่าง transcript segment" เท่านั้น ไม่รับ `voice_segments` เลย
3. **Whisper รวมหลายประโยคไว้ท่อนเดียว** (CLAUDE.md 3.2.1: p90 = 20 วิ) ความเงียบกลางท่อนจึงไม่ปรากฏเป็นช่องว่างระหว่างท่อน — วัดจริง: V02 และ V07 มีช่องว่างระหว่างท่อน ≥ 3.0 วิ = 0 ช่วง (`before/measure_silence_sources.txt`)
4. **threshold:** `SILENCE_HINT_MIN_GAP = 3.0` ([ai_logic.py:63](../backend/core/ai_logic.py#L63)) มีเงื่อนไขขั้นต่ำเดียวคือความยาว ≥ 3.0 วิ ; ไม่มีการกรองอื่นก่อนส่ง Gemini นอกจากตัดที่ 15 ช่วงแรก (`limit=15`)
5. **Gemini เห็นแค่เวลาระดับท่อน** ตาม `_slim_for_gemini` (start/end/text) จึงชี้ความเงียบกลางท่อนเองไม่ได้ — hint คือทางเดียวที่นำข้อมูลนี้เข้า prompt ได้ตาม architecture ปัจจุบัน
6. ผลปลายทางยังถูกจำกัดโดย **Step 5 ที่ทิ้งช่วงตัด ≤ 5.0 วิ** ([ai_logic.py:2638](../backend/core/ai_logic.py#L2638)) และกฎในพรอมป์ "แต่ละช่วงที่จะลบต้องยาวอย่างน้อย 5 วินาที" — **ไม่ได้แก้ในรอบนี้** (นอกขอบเขต)

## 3. Previous Behavior

```
Video ─→ VAD (Silero) ─→ voice_segments ─┐   (voice_segments ใช้ที่: filter_transcript_by_vad, _protect_outro,
       └→ Whisper → transcript ──────────┤    _spare_unreadable_speech — ไม่เคยใช้คำนวณช่วงเงียบ)
                                         ├→ filter_transcript_by_vad  (ปรับเป็นสัดส่วนเสียงพูดแล้ว ใน vad-fix-v1)
                                         ├→ _long_silence_gaps(transcript)   ← เฉพาะช่องว่างระหว่างท่อน ≥ 3.0 วิ
                                         │      └→ _format_silence_hint → ใส่ในพรอมป์ deletion
                                         └→ Gemini → Step 5 (ทิ้งช่วง ≤ 5 วิ + snap) → invert → Snap → Guards → Final cut
```

## 4. New Design

หลักการ: เพิ่ม **แหล่งข้อมูลที่สอง** เข้า hint เดิม โดยไม่เพิ่มกลไกใหม่และไม่แก้พรอมป์

- `_long_silence_gaps(..., voice_segments=)` รวม 2 แหล่งเป็นรายการเดียว: (1) ช่องว่างระหว่างท่อนแบบเดิม (2) ช่วงเงียบจาก VAD ภายในท่อน ผ่าน guard ; ช่วงที่ทับกันถูกรวมเป็นช่วงเดียว
- ส่งต่อเป็น **structured hint แบบเดิม** (`{"start","end"}` ผ่าน `_format_silence_hint`) — ข้อความพรอมป์ **ไม่เปลี่ยน** (ยืนยัน: พรอมป์ของ V01, V03, V05 ที่ hint ไม่เปลี่ยน เหมือนเดิมทุกไบต์)
- **reuse `get_silence_gaps()` ที่มีอยู่แล้ว** (ไม่เขียนตรรกะซ้ำ) ผ่าน `import` ตอนเรียก ไม่ใช่ตอนโหลดโมดูล เพราะ `vad_logic` โหลดโมเดล Silero ทันทีที่ import
- **guard (ห้ามเอาช่วงที่มีเสียงพูดมาเป็น "เงียบ"):** ช่วงที่ส่งต่อต้อง (ก) อยู่ในช่วงที่ VAD ไม่เห็นเสียงพูด (โดยนิยามของ `get_silence_gaps`) และ (ข) ไม่มีคำของ Whisper ทับ — หักช่วง `[start,end]` ของคำออก แล้วเก็บเศษที่ยาว ≥ 3.0 วิ ; ท่อนที่ไม่มี `words[]` พึ่ง VAD อย่างเดียว ; import `vad_logic` ล้ม → พิมพ์คำเตือนและใช้เฉพาะแหล่งเดิม
- ไม่ส่ง `voice_segments` → ทำงานเหมือนเดิมทุกประการ (ยืนยันกับ transcript จริงทั้ง 7 คลิป)

**threshold ที่ใช้: 3.0 วิ ไม่เปลี่ยน — เหตุผลจากข้อมูลจริง** (VAD silence gap ทุกคลิป เรียงความยาว):
`2.0, 2.1, 2.3, 2.6, 2.8 | 4.3, 4.6, 4.8, 4.9, 5.2, 6.5, 12.9, 15.4, 19.7` → แยกเป็น 2 กลุ่มชัด (≤ 2.8 วิ: 5 ช่วง · ≥ 4.3 วิ: 9 ช่วง) ไม่มีช่วงใดอยู่ระหว่าง 2.8–4.3 ดังนั้นเกณฑ์ใดใน (2.8, 4.3] ให้ชุดเดียวกัน ค่าเดิม 3.0 อยู่ในช่วงนี้ จึงไม่มีเหตุให้เปลี่ยน
**หลักฐานที่ต้องใช้ guard คำของ Whisper:** 7 จาก 14 ช่วงเงียบของ VAD (≥ 2.0 วิ) มีคำที่ Whisper เริ่มพูดข้างใน (ทับ 0.0–0.8 วิ ส่วนใหญ่ที่ขอบ) เช่น V07 59.0–61.1 (2.0 วิ) มีคำจริง 2 คำ

  - เพิ่ม `_vad_silence_gaps()` ([บรรทัด 964](../backend/core/ai_logic.py#L964))
  - ขยาย `_long_silence_gaps()` ให้รับ `voice_segments` ([บรรทัด 1020](../backend/core/ai_logic.py#L1020))
  - จุดเรียก ([บรรทัด 2450](../backend/core/ai_logic.py#L2450)) ส่ง `voice_segments=` เพิ่ม
- **ไม่ได้แตะ:** `filter_transcript_by_vad`, Snap, guard เทคซ้ำ, พรอมป์ Gemini, visual, ซับ, render, frontend, `tasks.py`, `vad_logic.py`
- **log ใหม่** (ไม่พิมพ์ข้อความของผู้ใช้):
```
[Silence Gap] detected = 3 (between-segments 0, VAD 3) | usable = 3
  segment=1 (34.4-65.4) internal gap 47.4-51.5 duration=4.2 action=KEEP_AS_HINT
  gap <start>-<end> duration=<d> action=IGNORE reason=speech_inside(Whisper words)   ← รูปแบบบรรทัด IGNORE (ไม่พบกรณีนี้ในข้อมูลจริง)
```
  `detected` = ช่วงดิบจากทั้งสองแหล่ง · `usable` = ช่วงที่ส่งเป็น hint หลังรวม/guard

## 11. Limitations

1. **ผลปลายทางครบ 4/4 คลิปที่กำหนดแล้ว** (V02, V06 full, V06 summary, V07 full — rerun2 สำเร็จ 2026-09-22 14:06 หลังโควตาเปิด) แต่ **V01, V03, V04, V05 ยังไม่มีผลปลายทางเลย** (นอกขอบเขต harness รอบนี้) · V02 ไม่มี control ในเซสชันเดียวกัน (503 ทุก key×model) จึงเปรียบเทียบได้กับรอบก่อนเท่านั้น (คนละเซสชัน)
2. **n = 1 ต่อ run และ Gemini ไม่แน่นอนอย่างมาก** (พิสูจน์แล้วซ้ำหลายครั้ง: V06 full BEFORE→CONTROL recall 65.8%→50.6% ; V06 summary BEFORE→CONTROL recall 36.1%→78.0% ; V06 summary CONTROL→NEW recall 78.0%→42.3% ทั้งที่ NEW ไม่ได้ใช้ hint เงียบเลย) — ความแปรปรวนระดับนี้ใหญ่กว่าผลต่างที่คาดจาก Silence Gap Fix เอง ทำให้เทียบ n=1 ต่อคู่ไม่น่าเชื่อถือพอจะสรุปเชิงสถิติ (V02 จึงยังเป็นผล "ชั่วคราว" แม้มีหลักฐานเชิงกลไกสนับสนุน)
3. **เป็น hint ไม่ใช่การตัดเอง — พิสูจน์แล้วทั้ง 2 ทิศทาง:** Gemini อาจเมิน hint จริง (V06 summary rerun2 — ไม่หยิบ hint ไปใช้เลยทั้งที่ถูกส่งเข้าพรอมป์ถูกต้อง) และช่วงที่สั้นกว่า 5 วิถูกทิ้งเสมอ (ไม่ได้แก้) — V02 ช่วง 4.2 วิ และ V06 full ช่วง 3.6/4.3 วิ ตัดไม่ได้ภายใต้กฎเดิม
4. **hint อาจชี้ไปที่การเว้นจังหวะตั้งใจ:** V02 30.4–33.7 (3.3 วิ) ตรงกับ SHOULD_KEEP ของผู้ใช้ — รอบนี้ Gemini ไม่ตัด (สั้นกว่า 5 วิ) แต่ถ้าเป็นช่วงยาวกว่า 5 วิที่ตั้งใจเว้น ระบบแยกไม่ได้นอกจากคำในพรอมป์ "เว้นแต่เป็นการเว้นจังหวะที่ตั้งใจ"
5. **ข้อมูลเดิมที่ไม่ได้แก้:** ช่องว่างระหว่างท่อนแบบเดิมใน V04/V05/V06 ทับเสียงพูดตาม VAD 3.2/4.1/4.3 วิ (Silero ไวต่อลม/noise) — ยังส่งเป็น hint ตามเดิม ; การเปลี่ยนต้องตัดสินใจแยกเพราะเปลี่ยนพฤติกรรมที่มีอยู่
6. **ความแม่นของ guard ด้านที่ต้อง IGNORE** ตรวจด้วยข้อมูลสังเคราะห์เท่านั้น (ไม่มีกรณี IGNORE ในข้อมูลจริง)
7. harness ฉีด transcript จาก baseline (ไม่ถอด Whisper ใหม่) ; V04 มี hint เพิ่ม (71.1–75.7) ที่ยังไม่ทราบผลปลายทาง (ไม่อยู่ใน 4 คลิปที่กำหนดไว้ให้รัน)
8. F1 รวมนิยามสองแบบ (R ตามประเภทที่โหมดอนุญาต, P ตามทุกประเภท)
9. **บั๊ก `_word_bound`/Snap ที่บล็อกผล V07 ถูกแก้แล้วในรอบแยก (commit `6decc1d`, นอก scope ของ Silence Gap Fix)** — รายละเอียดผลหลังแก้อยู่ใน `eval/snap-wordbound-fix-report.md` ไม่ใช่ส่วนหนึ่งของรายงานนี้ ไม่ควรนับผลของบั๊กนั้นเป็นผลของ Silence Gap Fix

## 12. Conclusion

- **ระดับ technical: ผ่านครบทั้งข้อ 1–5** — ระบบตรวจพบช่วงเงียบภายในท่อนจากข้อมูลจริง (V02 0→3, V07 0→3), ส่งเข้าสู่ขั้น decision (hint ในพรอมป์ deletion และ log จริงของ pipeline), transcript ที่มีเสียงพูดไม่ถูกทิ้ง, มีหลักฐานทำซ้ำได้ ; ข้อ 4 (ไม่มี regression จาก VAD Fix) **ผ่านครบทั้ง 4 คลิปที่กำหนดไว้แล้ว** (V02, V06 full, V06 summary, V07 full — ปลายทางครบทุกคลิป)
- **ยังสรุปไม่ได้ว่า "Recall ปลายทางสูงขึ้น" จาก Silence Gap Fix เอง** — แม้ตอนนี้มีผลปลายทางครบ 4/4 คลิปแล้ว แต่**ไม่มีกรณีใดเลยที่ hint เงียบไปถึงผลปลายทางได้สำเร็จแบบไม่ติดอุปสรรค ยกเว้น V02 (n=1, ไม่มี control คู่)** — V06 full ติด Step 5 (ช่วง ≤5s ถูกทิ้ง), V07 full ติดบั๊ก `_word_bound`/Snap คนละตัว (Gemini ใช้ hint ถูกต้องแล้วแต่ downstream พัง — แก้แยกแล้วนอก scope นี้), V06 summary Gemini เลือกไม่ใช้ hint เอง — เป็น 3 กลไกที่แยกจาก Silence Gap Fix เองทั้งหมด ไม่ใช่ตัว fix ทำงานผิด
- **สิ่งที่ยืนยันได้แน่นอน:** ตัว fix ทำงานถูกต้องที่ "ระดับ input และการตัดสินใจของ Gemini" (ตรวจพบช่วงเงียบถูกต้อง, guard ไม่ทับเสียงพูด/คำ 0.00 วิทุกคลิป, ส่งเป็น hint ที่ Gemini นำไปใช้ได้จริงเมื่อผ่านเงื่อนไข ≥5 วิ — พิสูจน์แล้วทั้งใน V02 และ V07)
- **เพดานของผลลัพธ์อยู่ที่กฎ 5 วินาทีเดิม + ความแปรปรวนของ Gemini ในการเลือกใช้ hint** ไม่ใช่ที่ตัว fix เอง: ช่วงเงียบ 3–5 วิ ตรวจพบแล้วแต่ตัดไม่ได้ (Step 5) — เป็นประเด็นแยกที่ต้องตัดสินใจ (เกี่ยวกับความถี่ของรอยตัดที่ทำให้ภาพกระโดด), ไม่ใช่ scope ของรอบนี้
- **สถานะ:** ข้อมูล final-output ครบ 4/4 คลิปตามที่กำหนดไว้แล้ว (rerun2 เสร็จสิ้น) — commit source แล้วที่ `1612888` (`fix: expose VAD-confirmed internal silence gaps`) พร้อมหลักฐานทั้งหมด
