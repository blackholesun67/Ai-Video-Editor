## อาการ (ยืนยันด้วย log จริงของการรัน Gemini จริง)

`V07_full` (new, ใช้ `gemini-2.5-flash`) — Gemini เสนอตัด **3 ช่วงเงียบพอดีตาม hint ที่ Silence Gap Fix เพิ่มเข้าไป** (รวม 46.4 วินาที จาก 94.9 วินาที):

```
🔴 [high] 16.83s → 31.49s (14.7s) — ช่วงเงียบที่ยาวผิดปกติ
🔴 [high] 37.12s → 49.2s (12.1s) — ช่วงเงียบที่ยาวผิดปกติ
🔴 [high] 62.97s → 82.63s (19.7s) — ช่วงเงียบที่ยาวผิดปกติ
```

แต่ผลสุดท้ายกลับเป็น **`selected_segments` แค่ 1 ช่วง ครอบทั้งคลิป (0.0s → 94.87s)** — เหมือนไม่มีอะไรถูกตัดเลย
ทั้งที่ทุกช่วงยาวเกิน 5 วินาที (Step 5 ไม่เกี่ยวข้องกับเคสนี้)

## ต้นเหตุ (ยืนยันด้วยการรันฟังก์ชันจริงทีละขั้น ไม่ใช่การเดา — ดู `eval/tools/trace_v07_collapse.py`)

Transcript ของ V07 มีแค่ **2 ท่อน (Whisper segment) ยาวท่อนละ ~40-50 วินาที** และช่วงเงียบทั้ง 3 อยู่
**ภายใน** ท่อนเดียวกัน (ไม่ใช่ระหว่างท่อน) เมื่อ invert ช่วงตัดทั้ง 3 ของ AI จะได้ 4 ช่วงที่เก็บ:

```
[0, 16.83] [31.49, 37.12] [49.2, 62.97] [82.63, 94.87]
```

แต่ละช่วงถูกส่งเข้า `_snap_segments_to_sentences` → `_snap_bounds()` ([ai_logic.py:1814](../../backend/core/ai_logic.py#L1814))
ทีละช่วง ผลจริงจากการรัน:

```
[0.0, 16.83]      -> ไม่เปลี่ยน
[31.49, 37.12]    -> [15.95, 50.16]   ← ขยายออกทั้ง 2 ด้าน กิน 2 ช่วงเงียบข้างเคียงทั้งคู่
[49.2, 62.97]     -> [49.2, 82.71]    ← ขยายท้ายออก กินช่วงเงียบที่ 3 ทั้งหมด
[82.63, 94.87]    -> ไม่เปลี่ยน
```

กลไกที่ทำให้ขยายไกลขนาดนี้: ขอบที่ต้องขยับ (เช่น `31.49`) ห่างจากขอบท่อน Whisper (`0.0`) เกิน
`SNAP_MAX_SENTENCE` (6.0 วิ) โค้ดจึงตกไปใช้ **`_word_bound()`** ([ai_logic.py:1794](../../backend/core/ai_logic.py#L1794))
ซึ่งเดิน `words[]` ของท่อนนั้น **หาคำที่ใกล้ที่สุดแบบไม่มีเพดานระยะทาง** — พอมีช่วงเงียบยาวคั่นอยู่
(นี่คือสิ่งที่ VAD/Gemini เพิ่งตัดสินใจตัด) คำที่ "ใกล้ที่สุด" ก็คือคำก่อน/หลังช่วงเงียบนั้น ซึ่งอยู่ไกล
ถึง 12-20 วินาที — ฟังก์ชันนี้ไม่รู้ว่ากำลังข้ามช่วงเงียบอยู่ จึงยืดข้ามไปเลย

ผลคือช่วงที่เก็บทั้ง 4 ทับซ้อนกันหลังขยาย แล้ว `merge_close_segments(gap_threshold=0.0)` (บรรทัดสุดท้าย
ของ `_snap_segments_to_sentences`) รวมทุกช่วงที่ทับกันเป็นก้อนเดียว → **กลืนช่วงเงียบทั้ง 3 กลับมาหมด**
เท่ากับ "ไม่ตัดอะไรเลย" ซึ่งบังเอิญมีค่าเท่ากับผลของ control (ที่ไม่เคยเสนอตัดอะไรเลยตั้งแต่แรก) — ตัวเลข
ปลายทางจึงดูเหมือนไม่ต่างกัน (recall 0.0% ทั้งคู่) **แต่คนละสาเหตุกันโดยสิ้นเชิง**

ยืนยันด้วย `words[]` จริงจาก transcript (ไม่ใช่ข้อมูลที่ถูกตัดออกตอนบันทึก `preview.json` — มีครบ 211/182 คำ):
```
seg 0.0-52.58 : GAP 16.83 -> 31.58 (14.75s) ; GAP 37.0 -> 49.2 (12.2s)
seg 55.15-94.87: GAP 62.92 -> 82.63 (19.71s)
```
ตรงกับช่วงเงียบทั้ง 3 ที่ Gemini เสนอตัดเป๊ะ — ไม่ใช่สิ่งประดิษฐ์จากวิธีทดสอบ (harness ฉีด transcript จาก
`preview.json` จริง ที่มี `words[]` ครบ ไม่ใช่ transcript ที่ถูกตัดข้อมูลออก)

## ทำไมก่อนหน้านี้ไม่เคยเจอบั๊กนี้

บั๊กนี้ซ่อนอยู่ในโค้ดมาตั้งแต่ก่อน Silence Gap Fix แต่ไม่เคยแสดงอาการ เพราะ**ไม่เคยมีใครสั่งตัดช่วงเงียบ
ภายในท่อนยาว ๆ แบบนี้มาก่อน** — Silence Gap Fix คือสิ่งที่ทำให้ Gemini เห็นและเลือกตัดช่วงแบบนี้ได้เป็นครั้งแรก
จึงเพิ่งไป "ปลุก" บั๊กที่มีอยู่แล้วให้แสดงผล ไม่ใช่บั๊กที่ Silence Gap Fix สร้างขึ้นใหม่

`V02` (ที่เคยรายงานว่าตัดสำเร็จ, recall 50.6%) ไม่โดนบั๊กนี้ เพราะเสนอตัดแค่ 1 ช่วงในรอบนั้น (ไม่มีช่วงเก็บ
ข้างเคียงให้ทับซ้อนกันจนรวมกันหมด) — ยังไม่ได้ตรวจว่าโครงสร้างท่อนของ V02 ต่างจาก V07 อย่างไรกันแน่ ต้องดูเพิ่ม

## ผลกระทบต่อการตีความรอบทดสอบนี้

- **V07 full:** Silence Gap Fix "ทำงานถูกต้องที่ระดับการตัดสินใจของ Gemini" (เสนอตัดตรง hint เป๊ะ) แต่ผล
  ปลายทางถูกบั๊กนี้ลบล้างจนเท่ากับ "ไม่ตัดอะไรเลย" — ไม่ใช่ความล้มเหลวของ Silence Gap Fix เอง แต่เป็นบั๊กที่มีอยู่
  ก่อนแล้วในโค้ดส่วนอื่น (`_snap_bounds`/`_word_bound`)
- ต่างจาก `V06 full` ที่ถูก **Step 5 (ตัดช่วง ≤5 วิทิ้ง)** บล็อกไว้ (คนละกลไกกัน คนละจุดในโค้ด)
- ต่างจาก `V06 summary` (new) ที่ Gemini **ไม่เลือกใช้ hint เลยในรอบนี้** (ความแปรปรวนของ Gemini ธรรมดา
  ไม่เกี่ยวกับบั๊กนี้หรือกับ Silence Gap Fix)

## แนวทางแก้ที่แนะนำ (ยังไม่ทำ)

`_word_bound()` ควรมีเพดานระยะทาง (เช่นเดียวกับที่ `_snap_bounds` มี `SNAP_MAX_SENTENCE`/`SNAP_MAX_EXTEND`
คุมเส้นทางอื่นอยู่แล้ว) หรือควรหยุดเดินเมื่อเจอช่องว่างระหว่างคำที่กว้างเกินเกณฑ์หนึ่ง (เช่น `SENTENCE_PAUSE`
หรือค่าที่ใกล้เคียงกับที่ `_vad_silence_gaps`/`SILENCE_HINT_MIN_GAP` ใช้อยู่แล้ว) แทนที่จะเดินหาคำที่ใกล้ที่สุด
โดยไม่จำกัดระยะทาง — ต้องวัดกับ transcript จริงหลายคลิปก่อนตั้งค่า ไม่ใช่เดา (กฎข้อ 3 ใน CLAUDE.md)
